5. [ ] Displays equity curve chart showing portfolio value over time

8. [ ] No complex calculations - just signal → position → track performance

## Dev Notes

### Core Architecture Principle
This is a SIMPLE backtesting system. No synthetic data, no complex calculations, no correlations. Just:
1. Fetch real prices
2. Calculate signal (using existing calculators)
3. Determine position
4. Track performance

### Signal Trading Rules

```typescript
// Utilities/SPY Signal
if (XLU/SPY > threshold) {
  position = 'XLU';  // Risk-Off
} else {
  position = 'SPY';  // Risk-On
}

// Lumber/Gold Signal
if (WOOD/GLD > threshold) {
  position = 'SPY';  // Risk-On
} else {
  position = 'GLD';  // Risk-Off
}

// Treasury Curve Signal
if (IEF/TLT > threshold) {  // Curve steepening
  position = 'SPY';  // Risk-On
} else {
  position = 'TLT';  // Risk-Off
}

// SP500 Moving Average
if (SPY > MA200) {
  position = 'SPY';  // Risk-On
} else {
  position = 'IEF';  // Risk-Off
}

// VIX Defensive
if (VIXY < threshold) {  // Using VIXY ETF as proxy for VIX
  position = 'SPY';  // Risk-On
} else {
  position = 'TLT';  // Risk-Off
}
```

### Railway Backend Integration

**Railway Response Structure (Existing Endpoint)**

**Endpoint:** `GET /api/v2/market-data`

**Request:**
```typescript
// Query parameters:
?symbols=SPY,XLU,WOOD,GLD,IEF,TLT,VIXY    // Comma-separated symbols (required)
&useCache=true                              // Enable caching (optional, default: true)
&fallbackEnabled=true                       // Enable fallback to other sources (optional, default: true)
```

**Example:**
```
GET https://gayed-backend-production.up.railway.app/api/v2/market-data?symbols=SPY,XLU,WOOD,GLD
```

**Response (MarketDataResponse):**
```typescript
{
  success: true;
  result: {
    data: Array<{
      symbol: string;
      date: string;
      close: number;
      volume?: number;
      // ... other OHLC fields
    }>;
    source: string;           // 'tiingo' | 'yahoo' | 'cache'
    quality: {
      score: number;          // 0-1 scale
      issues: string[];
    };
    provenance: {
      fetchId: string;
      source: string;
      timestamp: string;
      symbols: string[];
      success: boolean;
    };
    cached: boolean;
    timestamp: Date;
  };
  timestamp: string;          // ISO timestamp
}
```

**Error Response:**
```typescript
{
  success: false;
  error: string;
  timestamp: string;
}
```

### Performance Calculation
```typescript
interface BacktestResult {
  totalReturn: number;      // (finalValue / initialValue - 1) * 100
  numberOfTrades: number;    // Count of all buy/sell transactions
  winRate: number;          // profitableTrades / totalTrades * 100
  maxDrawdown: number;      // Largest peak-to-trough decline
  trades: TradeRecord[];    // Complete history
  equityCurve: {           // Daily portfolio values
    date: string;
    value: number;
  }[];
}
```

#### **Root Cause Hypothesis**

**Theory A: Railway Backend Response Missing Quality Field**
- Railway backend `UnifiedDataService.fetchMarketData()` returns `MarketDataResult` with `quality` field
- Server.ts wraps as `{ success, result, timestamp }`
- Frontend expects `result.quality` to exist
- **Likely Issue:** Railway backend is **failing to execute** `validateDataQuality()` (line 139) due to:
  - Missing data from Tiingo API
  - Circuit breaker open (repeated failures)
  - Database connection failure (PostgreSQL unavailable)
  - Error thrown before quality validation runs

**Theory B: Railway Backend Unreachable**
- Railway deployment at `gayed-backend-production.up.railway.app` is **offline**
- RailwayClient fallback not working correctly
- Network timeout causing incomplete response

**Theory C: Type Mismatch in Date Handling**
- `startDate` and `endDate` passed as strings from frontend
- Railway backend expects `Date` objects in `fetchOptions` (server.ts:192-197)
- Type conversion may be failing silently
