  ```typescript
  async function validateBacktestData(railwayResponse: SignalV2Response): ValidationResult {
    const quality = railwayResponse.metadata.quality;

    // Check 1: Minimum quality score
    if (quality.averageScore < 0.8) {
      return { valid: false, reason: 'Quality score below 0.8' };
    }

    // Check 2: Data freshness
    const cached = railwayResponse.metadata.timing.cached;
    if (!cached && railwayResponse.metadata.timing.totalMs > 5000) {
      console.warn('Data fetch took longer than expected');
    }

    // Check 3: Completeness
    const expectedSymbols = ['LBS', 'GC=F'];
    const receivedSymbols = railwayResponse.data.map(s => s.type);
    if (!expectedSymbols.every(s => receivedSymbols.includes(s))) {
      return { valid: false, reason: 'Incomplete data' };
    }

    return { valid: true };
  }
  ```

## Dev Notes

### Railway Backend Integration Pattern

**Data Flow (Option A):**
```
Frontend (Vercel) → Railway Backend → UnifiedDataService → Data Sources
    ↓                    ↓                    ↓
Backtesting UI    /api/v2/signals     PostgreSQL/Redis
```

**Railway Backend V2 API:**
- **URL:** `https://gayed-signals-backend-production.up.railway.app`
- **Endpoint:** `/api/v2/signals`
- **Authentication:** Bearer token via `Authorization` header
- **Response includes:** Quality metrics, provenance, PostgreSQL persistence, Redis caching

### Key Railway Response Structure

```typescript
interface SignalV2Response {
  success: boolean;
  data: SignalV2[];
  metadata: {
    sources: {
      primary: 'postgresql' | 'redis' | 'live';
      failedSources: string[];
    };
    quality: {
      averageScore: number; // 0-1 scale
      issues: string[];
    };
    timing: {
      totalMs: number;
      cached: boolean;
    };
  };
}
```

### Critical Implementation Notes

2. **NEVER generate synthetic data** - Fail gracefully instead
3. **Respect feature flags** - Support NEXT_PUBLIC_USE_RAILWAY_BACKEND

5. **Handle fallback gracefully** - Railway → Local → Error
6. **Log migration metrics** - Track which backend served request
7. **Reuse existing Railway client** - Don't create duplicate clients

### PostgreSQL Schema (Managed by Railway Backend)

**Note:** Backend manages these tables. Frontend only reads via Railway API.

```sql
-- Market data table (Railway PostgreSQL)
CREATE TABLE market_data (
  id SERIAL PRIMARY KEY,
  symbol VARCHAR(10) NOT NULL,
  date DATE NOT NULL,
  close DECIMAL(10, 2) NOT NULL,
  volume BIGINT,
  source VARCHAR(50),
  quality_score DECIMAL(3, 2),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(symbol, date)
);

-- Data provenance table (Railway PostgreSQL)
CREATE TABLE data_provenance (
  id SERIAL PRIMARY KEY,
  data_id INTEGER REFERENCES market_data(id),
  source VARCHAR(50),
  fetch_time TIMESTAMP,
  transformations JSONB,
  quality_metrics JSONB
);
```
