## Migration Note
The original Story 4.0i attempted to retrofit the existing backtesting orchestrator with Railway backend data. However, investigation revealed:
- The UI at `/backtrader` expects a Python Backtrader service at `localhost:5000`
- The API route `/api/backtrader` has no working backend
- The sophisticated synthetic data generation in orchestrator.ts is disconnected from the UI
- Trying to "fix" this would require building the missing Python service or completely rewiring the architecture

Story 4.0j takes a simpler approach: build a new, focused backtesting system specifically for Gayed signals.

    // Check 3: Completeness
    const expectedSymbols = ['LBS', 'GC=F'];
    const receivedSymbols = railwayResponse.data.map(s => s.type);
    if (!expectedSymbols.every(s => receivedSymbols.includes(s))) {
      return { valid: false, reason: 'Incomplete data' };
    }

    return { valid: true };
  }

  export async function POST(request: NextRequest) {
    const { startDate, endDate, symbols } = await request.json();

    try {
      let marketData;

      // Use Railway backend if enabled

          const response = await marketDataService.getMarketData({

            endDate
          });

      // No synthetic data - return error

## Dev Notes

### Railway Backend Integration Pattern

**Data Flow:**
```
Frontend (Vercel) → Railway Backend → UnifiedDataService → Tiingo API
    ↓                    ↓                    ↓              ↓
Backtesting UI    /api/v2/market-data  PostgreSQL/Redis  Raw OHLCV Data
                  /api/v2/signals
```

**Railway Backend V2 API:**
- **URL:** `https://gayed-backend-production.up.railway.app`
- **Existing Endpoint:** `/api/v2/signals` (calculated signals)
- **New Endpoint:** `/api/v2/market-data` (raw OHLCV data from Tiingo)
- **Authentication:** Bearer token via `Authorization` header
- **Response includes:** Quality metrics, provenance, PostgreSQL persistence, Redis caching

### Key Railway Response Structures

### PostgreSQL Schema (Managed by Railway Backend)

**Note:** Backend manages these tables. Frontend only reads via Railway API.

```sql
-- Market data table (Railway PostgreSQL)
CREATE TABLE market_data (
  id SERIAL PRIMARY KEY,
  symbol VARCHAR(10) NOT NULL,
  date DATE NOT NULL,
  close DECIMAL(10, 2) NOT NULL,
  volume BIGINT,
  source VARCHAR(50),
  quality_score DECIMAL(3, 2),
  created_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(symbol, date)
);

-- Data provenance table (Railway PostgreSQL)
CREATE TABLE data_provenance (
  id SERIAL PRIMARY KEY,
  data_id INTEGER REFERENCES market_data(id),
  source VARCHAR(50),
  fetch_time TIMESTAMP,
  transformations JSONB,
  quality_metrics JSONB
);
```
