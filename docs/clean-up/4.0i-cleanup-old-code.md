# Story 4.0i: Clean Up Legacy Code After Railway Migration

**Epic:** 4.0 Data Pipeline Restructuring
**Story ID:** 4.0i
**Priority:** Medium
**Status:** 🟡 Blocked (Awaiting Railway Backend Validation)
**Depends On:** Story 4.0h (Railway Backend Integration)

---

## Story

**As a** development team,
**I want** to remove legacy signal calculation and market data fetching code,
**so that** we have a single, maintainable data pipeline through Railway backend without technical debt.

---

## Acceptance Criteria

1. **Pre-Cleanup Validation**
   - [ ] Railway backend running in production for 30+ days
   - [ ] Railway success rate > 99.5% consistently
   - [ ] Zero critical data quality incidents
   - [ ] Local API fallback usage < 0.5%
   - [ ] Team consensus that Railway backend is stable

2. **Legacy Service Removal**
   - [ ] `SignalService.ts` deleted (signal calculation)
   - [ ] `enhanced-market-client.ts` deleted (Tiingo/Alpha Vantage)
   - [ ] `fred-api-client.ts` deleted (FRED API client)
   - [ ] `dol-api-client.ts` deleted (DOL API client)
   - [ ] All references updated to use Railway backend

3. **Local API Route Removal**
   - [ ] `/api/signals/route.ts` deleted
   - [ ] All direct fetch calls updated to `fetchSignalsWithFallback()`
   - [ ] Deprecation headers removed (no longer needed)
   - [ ] API route completely removed from routing

4. **Dependency Cleanup**
   - [ ] Unused npm packages identified
   - [ ] `package.json` cleaned of unnecessary dependencies
   - [ ] `npm prune` executed to remove unused packages
   - [ ] Bundle size reduction verified

5. **Code Reference Updates**
   - [ ] All imports of old services removed
   - [ ] TypeScript compilation successful
   - [ ] No dead code remaining
   - [ ] ESLint warnings addressed

6. **Documentation Updates**
   - [ ] Architecture docs updated to reflect Railway-only approach
   - [ ] Coding standards updated (remove local API patterns)
   - [ ] README updated with new data flow
   - [ ] CLAUDE.md updated with Railway backend as sole pattern

7. **Testing Updates**
   - [ ] Tests updated to use Railway backend
   - [ ] Mock data tests removed (real data only)
   - [ ] Integration tests use Railway backend exclusively
   - [ ] All tests passing
