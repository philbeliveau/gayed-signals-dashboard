## 🚨 Rollback Plan

### **If Issues Arise During Cleanup:**

**Immediate Rollback (< 5 minutes):**
```bash
# Revert the cleanup commit
git revert HEAD
git push origin main

# Re-deploy previous version
# (Vercel/Railway auto-deploys)
```

**Partial Rollback (Restore Specific Files):**
```bash
# Restore local API route only
git checkout HEAD~1 -- apps/web/src/app/api/signals/route.ts
git commit -m "fix: Restore local API route temporarily"
git push origin main
```

**Full Rollback (Restore Feature Flag):**
```bash
# Restore feature flag system
git checkout HEAD~1 -- apps/web/src/lib/feature-flags.ts
git checkout HEAD~1 -- apps/web/src/lib/api/fetch-signals.ts

# Re-enable local API as fallback
# Update .env:
NEXT_PUBLIC_USE_RAILWAY_BACKEND=false
```

### **Rollback Decision Criteria:**

**Immediate Rollback If:**
- Railway backend success rate drops below 95%
- Critical data quality issues detected
- User-facing errors spike
- Multiple customer complaints

**Investigate Before Rollback:**
- Isolated incidents (1-2 users)
- Minor performance degradation
- Non-critical bugs
